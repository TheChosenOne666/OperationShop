> 版本 v1.0 · 2026-09-14
> 上游文档：《需求文档》《玩法与技术方案》
> 本文件是模块排期与验收的唯一依据；每个模块完成后停下来等确认，不自动进入下一个

---

## 一、规划原则

1. **模块化推进，后端与单元测试优先**：每个模块按「后端接口 → 单元测试通过 → 客户端 → 联调验证 → 文档更新」的顺序走。
2. **每个模块必须有可独立验证的交付物**：说不清怎么验收的模块不进计划。
3. **完成一个模块就停下**，由你确认是否进入下一个模块。
4. **数值与规则不写进代码**，全部集中在规则配置里；调数值只改配置。
5. **没有设计图的页面不动工**，绝不脑补视觉。
6. **素材先处理再使用**：现有设计图全部是 JPG 假透明，抠图是独立的前置任务。
7. **文档随代码走**：任何新增/修改/删除都要同步更新对应文档，不留无文档的代码改动。

## 三、模块明细

### M01 本地开发后端 ✅ 已完成

- **目标**：把「开店 → 客流 → 收益 → 业务日刷新」的服务端权威闭环在本机跑通。
- **交付物**：`cmd/server`、`internal/game`、`internal/api`、`config/development.json`、`docs/M01-本地开发后端.md`。
- **验收结果**：`gofmt` / `go vet` 无告警，`go test -race` 全绿，`internal/game` 覆盖率 96.2%、`internal/api` 94.8%，真实进程端到端联调 17 项场景全部符合预期。
- **遗留**：`cmd/server` 靠端到端联调覆盖，无单元测试。

### M02 后端扩展：规则 v2、解锁与升级、动态客流

- **目标**：把《玩法与技术方案》A2–A5 的规则实现到服务端，并保持 M01 的存档自证基线。
- **交付物**：
  - 规则配置 v2（铺位解锁价格与顺序、等级单价表、满铺加成、基础客流 + 单店客流）
  - 存档 schema v2（`unlockedSlots`、`dailyVisitorCap`、`spent`、`level`、`segments`）
  - 新增接口：解锁铺位、升级店铺、关店
  - 校验规则按 B5.3 调整
  - 单元测试：正常路径 + 边界（金币不足、跳过解锁顺序、重复解锁、满级再升级、解锁后当日客流不变、单价变化时账单分段正确）
- **验收标准**：
  1. 金币不足时解锁失败，且状态与存档零变化。
  2. 试图跳序解锁二层铺位被拒绝。
  3. 重复解锁不重复扣费。
  4. 升级后新产生的收益按新等级单价记账，历史账单不被改写，且每一段 `revenue == visitors × unitPrice` 成立。
  5. 当天中途开店不改变当日客流上限，次日生效。
  6. 满铺加成在关掉同层任意一家店后立即失效。
  7. 未解锁铺位不得出现累计客流或收益。
  8. `gofmt` / `go vet` / `go test -race` 全绿。
- **风险**：存档 schema 变更会让旧存档被拒绝加载（预期行为）；开发期直接删档。
- **收尾**：更新 `docs/M01-本地开发后端.md` 或另立 `docs/M02-*.md`，并更新 `docs/玩法与技术方案.md` 中与本模块相关的实现状态。

### M03 素材管线

- **目标**：把现有设计图处理成引擎可直接使用的规范素材，并明确缺口。
- **交付物**：
  - `assets/textures/` 下按约定目录与命名整理的透明 PNG（店铺立绘、空铺位底图、顾客、UI 底板、图标）
  - 每张图的处理记录：原图 → 输出 → 尺寸 → 压缩后体积
  - 素材缺口清单（见第五节）确认版
- **验收标准**：抠图边缘干净无白边；尺寸统一到引擎规格；单张压缩后体积满足包体预算；导入引擎后无多余棋盘格残留。
- **风险**：AI 生成图边缘常有阴影与碎屑，需要人工抽检；部分素材（如楼梯、遮阳伞）只有主界面合成图里有，需要单独重出。
- **说明**：本模块与 M02 无依赖，可与 M02 并行推进。

### M04 客户端工程与主界面（只读联调）

- **目标**：Cocos 工程能构建出微信小游戏，主界面按设计图还原，并能读到服务端的真实数据。
- **交付物**：
  - 工程配置：设计分辨率 750×1334、适配策略、构建目标设为微信小游戏、AppID 配置
  - `Boot` / `Mall` 两个场景 + `Slot` / `ShopView` / `Guest` / `Hud` / `Panel` 预制体
  - 启动时拉取 `/api/v1/config` 与 `/api/v1/mall` 并驱动界面
  - 构建产物能在微信开发者工具中打开
- **验收标准**：
  1. 主界面与 `主界面图.jpg` 逐项比对一致：招牌、两层铺位顺序、底部 HUD 三段布局、客流分母与规则一致。
  2. 金币与客流显示的是服务端返回的真实值，不是写死的假数据。
  3. 未解锁铺位显示为空铺位素材。
  4. 构建产物的主包体积有明确数字，并记录在文档里。
- **前置**：M02 的字段（解锁状态、等级、客流上限）已就位；M03 的素材已可用。
- **风险**：这是本项目第一次用 Cocos Creator，构建链路、适配、包体积都是未知项，预留调试时间。

### M05 经营闭环

- **目标**：玩家能在主界面开店/关店，并看到客人到店与收益增长。
- **交付物**：开店与关店的交互；主界面每 5 秒结算轮询；客人走位、金币飘字、数字滚动补间；切后台停止轮询、回前台立即拉快照。
- **验收标准**：
  1. 开店后 5 秒内能看到第一位客人到店，金币增加、客流计数减少 1。
  2. 完全退出小游戏再进入，金币、客流、店铺开关状态完全一致。
  3. 界面数值永远以最近一次服务端响应为准，不出现金币跳变或回退。
  4. 关店后不再产生收益。
- **风险**：客人走位与轮询节奏不同步会出现"看到客人却没有收益"的错觉，需要把表现对齐到服务端返回的到店数。

### M06 页面与弹窗

- **目标**：补齐经营页、布局页、店铺详情、解锁/升级确认。
- **前置**：**这四处的设计图目前全部缺失，必须先补图。**
- **交付物**：经营页（各店状态与当日收益）、布局页（铺位解锁总览与下一铺位花费）、店铺详情弹窗（等级、单价、累计数据 + 升级入口）、解锁与升级确认弹窗。
- **验收标准**：逐屏与设计图核对字段、文案、布局、按钮状态；金币不足、已满级等异常态有明确提示且不出错。
- **风险**：无图动工必然返工，本模块的排期取决于设计图到位时间。

### M07 微信登录与云端存档

- **目标**：从本地开发令牌切到真实微信登录，存档上云。
- **前置**：微信小游戏 AppID **已就绪**（`wx5a00e2270436e6e0`，名称「街角百货铺」）；但工程尚未把 AppID 写入构建配置，属 M04 的活。类目是否支持目标玩法仍需确认。
- **交付物**：`code2session` 换 openid 与会话；客户端登录流程；存档云端化；本地开发令牌与"仅本机访问"限制的开关化。
- **验收标准**：
  1. 换设备或清缓存后，用同一微信账号进入，数据与服务端一致。
  2. 同一账号并发请求不会重复结算或重复扣费。
  3. 会话过期后能自动重新登录，不丢数据。
- **风险**：存档从单文件迁到云端会影响 M01 已有的原子替换与锁语义，需要重做并发与持久化方案。

### M08 好友经营排行榜

- **目标**：玩家能看到自己与微信好友之间的金币排行榜。
- **前置**：M07 完成；开放数据域与好友授权的规则**动手前必须核对官方最新文档**。
- **交付物**：主域上报权威金币到微信托管数据；开放数据域内渲染排行榜；无好友时的降级显示。
- **验收标准**：能拉到好友并正确显示自己的名次；一个好友都没有时显示自己的分数而不是空白页。
- **风险**：好友相关能力受平台授权与类目限制，若受限则按《玩法与技术方案》B7 的降级方案处理。

### M09 打磨与提审上线准备

- **目标**：可提审。
- **交付物**：性能优化记录、包体积确认、上线检查清单逐项确认、隐私协议与合规材料。
- **验收标准**：见第七节上线检查清单全部勾选。

## 四、推进顺序建议

**推荐顺序**：`M02 → M03（可与 M02 并行）→ M04 → M05 → M06 → M07 → M08 → M09`

**为什么 M02 排在 M04 前面**：主界面需要显示的数据里，铺位解锁状态、店铺等级、客流上限这三项都由 M02 定义。如果先做 M04，主界面的铺位与 HUD 会在 M02 落地后**再做一遍**。M01 已经把后端的底子铺好，M02 的增量不大，先用一个模块的成本换掉主界面的返工，划算。

**备选：M04 先行**。好处是更早暴露引擎风险（构建链路、包体积、真机表现都是本项目最大的未知数）；代价是主界面要返工。如果更担心"引擎这条路走不通"这个风险，可以先做一个只搭工程与静态布局、不接数据的 M04 探路版。

**并行建议**：M03 素材管线跟后端没有依赖，任何时候都可以并行起，而且它必须先于 M04 完成。

### 5.2 缺口

| 类别 | 缺什么 | 影响 |
| --- | --- | --- |
| 状态表现 | 店铺"已解锁未开业"与"已关店"的表现 | 可用明暗或滤镜处理现有立绘，不必重画，但需要确认视觉方案 |
| 顾客动画 | 行走帧或骨骼动画（现在只有静帧三视图） | 客人走动只能做整体位移，观感偏生硬 |
| 顾客多样性 | 多套顾客外观 | 长时间玩只看到同一张脸 |
| 场景细节 | 楼梯、遮阳伞、桌椅、盆栽（只存在于主界面合成图里） | 一层铺位之间的空隙需要这些填空 |
| UI 切图 | 弹窗/按钮的九宫格切图、按钮的选中与禁用态 | 弹窗和按钮状态无法还原 |
| 字体 | 与复古木质风匹配的中文字体（含授权） | 直接用系统字体会破坏整体调性 |
| 音效 | 点击、收银、金币入账等 | 第一版可无音效，但上线前建议补 |
| 页面设计图 | 布局页、经营页、好友页、各类弹窗 | **直接阻塞 M06** |
