### 现行核心口径（接手后按这个走）
- **冻结时机**：当日客流上限在「**首次实际产生客人的结算**」（`openShopCount ≥ 1`）时冻结落盘；**0 店开业不冻结、不落盘**
  - 为什么：客户端每 5 秒轮询会**先于玩家开店**触发首次结算，否则新账号上限会被冻成 20，与「开局 2 店全开 = 50」矛盾
- **「未冻结」表示**：显式 bool **`capFrozen`** 为唯一判据（**排除 `0` 作哨兵**——`0` 是合法整数域成员）
  - 存档：未冻结 ⇒ `dailyVisitorCap` 落盘占位 `0`；冻结与写值在**同一笔「先落盘再发布」事务内**原子完成
  - 接口：未冻结 ⇒ 返回 `null`；服务端保证 `dailyVisitorCap == null ⟺ capFrozen == false`
  - HUD：未冻结显示占位 `— / —`、**不显示分母**
  - 校验：已冻结 ⇒ 值落**合法档位集合** `{base + per × k | k ∈ [1,5]}`（**下界是 `base + per × 1`，`k = 0` 非法**）
- **字段归属**：`capFrozen` / `dailyVisitorCap` 是**存档字段、不是 config**（写进 config 会被 **ADR 0004 的配置指纹**误当规则变更；已回读 `service.go:244-249` 确认指纹覆盖整个 `Config`）
- **分段三个触发点**：① 开店（`prepare`）② 升级 ③ 满铺变化。`prepare` 硬顺序 = **置 `prepared` → 重算满铺 → 建/append 段**（不得调换）；触发满铺的新开业店**只产生一条 bonus 价段**、无 spurious 空段
- **每店分段数上界 ≤ 6**（1 初始 + 4 升级 + 1 满铺；满铺**不可逆**，故至多一次）
- **`unlockedSlots`**：无重复、构成 `unlockOrder` 前缀的 `slotId` 数组；未知 / 跳序 / 重复 / 数量越界 ⇒ 存档损坏拒绝加载。**写入强制规范顺序、读取不因顺序拒绝**（集合语义，质量侧已裁定）

- 对 ADR 类文档用「**标记作废 / 修订注引用原文 + 保留历史正文**」，对「现状实拍」类文档直接改正文 —— **两类文档处理方式不同，不可混用**
- 已知工具坑：**同一文件一次发多个 Edit 时偶发静默丢失**（工具仍报 success）→ 逐条串行 + grep 二次确认
- 🆕 **成员记录「用户拍板」时必须写明出处**（原话 / 时间 / 场合）；**无出处只能记「建议 / 待确认」** —— 防的是第 12 条的「自行发明了一个决定」
