## 4. 发现清单与处置

> 三条均为 P2。**没有一条会造成玩家看到错的数**，但 002-01 是玩家能看出的自相矛盾，需裁定。

### SC-M06-QA-002-01（P2）布局页同屏两个分子，且与稿 01 的数字不符 —— **成立，交裁定**

- **现象**：同一层，楼层标题「1 / 3 已开放」读**已解锁数**（`MallPages.ts:512` → `unlockedOn` `:631`），紧邻的满铺加成卡「二层 0 / 3 —— 再开放 3 个铺位」读**已营业数**（`:507` → `floorProgress` `:620`，判据是 `unlockedSlots` **且** `prepared`）。同词两义。
- **实测对照**：`.work/qa-m06-pop/runE.txt:18` 真实读数 `head2:"1 / 3 已开放"` 与 `boost:"二层 0 / 3 —— 再开放 3 个铺位即可获得 +1"` 同时出现。
- **根因不在代码，在稿自己**：稿 01 的 `:169` 那层是「衣橱 = 待开业 + 两个未开放」，加成卡 `:215` 却写「1 / 3 —— 再开放 2 个」= 拿**解锁数**当分子；而满铺加成的规则要的是**已开业**（`internal/game/service.go:415-421` `floorFull`：每个铺位既要 `unlocked` 又要 `Prepared`）。⇒ 照稿的字面数字实现，玩家解锁完三个铺位会看到「3 / 3」却没有加成，**稿的口径是错的**。
- **代码的选择是对的**（分子跟规则走），代价是与稿印出来的数字不一致 + 用词撞车。
- **处置**：登记为 `架构现状` §7.2 冲突 **R** 与本文件 §八-18，**两条出路交主理人裁**：① 改稿文案——加成卡分子改注明「已营业」，或措辞改「再让 K 家店开业」；② 维持稿面，接受标题与加成卡两口径并在文字上区分。本轮**未动代码**（避免复核对象漂移）。

### SC-M06-QA-002-02（P2）经营页列表整体下移 22px，底缘只剩 1px 安全余量 —— **成立，属对稿偏差**

- **现象**：稿 02 `.list` 顶 = **336**（`design/ui-mockups/02-经营页.html:43`、`:148`），实现取 **358**（`MallPages.ts:255`）；行高 146 + 间距 8 ×5 行 ⇒ 底缘 **1120**，而 HUD 160 + 上方 53 禁放线的边界是 **1121**（`1334 − 160 − 53`）。只差 1px；取稿值则有 23px 余量。
- **原因**：给页内错误提示位让出 22px（`MallPages.ts:248` 注释自陈）。但同一类提示位在**布局页**的处理方式是挪到顶栏右侧、不占列表上方（上一轮任务 4–5 实测记录的第 3 条），两页不一致。
- **另**：那行注释把出处写成 `docs/M06 §9.5`，实际该记录在 §10.1——指针指错节，属文档瑕疵。
- **处置**：登记 §八-18 第二条。建议出路 = 与布局页统一（提示位移顶栏右侧、列表回 336）。本轮**未改**；改后要出一次包用 `hud` 复核顶栏不重叠，属 e2e 范畴，不在本轮授权内。
