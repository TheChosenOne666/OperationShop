## 2. 工程结构

```
NewProject/
  assets/
    scene/Boot.scene            启动场景（手写，由编辑器 scene-2d 模板派生）
    scene/Mall.scene            主界面（手写，49 节点 / 147 对象，由 .work 内一次性生成器产出）
    scripts/
      ApiTypes.ts               服务端契约的客户端镜像（纯类型，编译期擦除）
      ApiClient.ts              只发请求、只抛稳定错误码，零本地计算（ADR 0001）
      Boot.ts                   开机取 config + mall，写进 Label
      MallScene.ts              主界面主控：取数 + 加载 Bundle + 三态与 HUD 渲染
      BuildConfig.ts            构建期生成、不入库（含开发令牌）
    bundles/
      mall-art/<类>/*.png       Asset Bundle `mall_art`：立绘/空铺底图/道具/客人（目标＝分包）
      ui-main/<类>/*.png        Asset Bundle `ui_main`：背景/HUD 木条/图标/状态遮挡件（主包内）
      ui-main/effects/slot-emissive.effect   铺位三态的自定义 2D 着色器（暴露 u_emissive）
    textures/app/*.png          **不进任何 Bundle**：app_icon / app_share 只给微信后台用
  settings/v2/packages/
    project.json                general.designResolution = 750×1334 / fitHeight
    engine.json                 功能裁剪（关掉 12 个 v1 不用的模块）
```

**设计分辨率**：`750×1334`、`fitWidth:false / fitHeight:true` → 构建产物里落成 `policy:3`（FIXED_HEIGHT），与《玩法与技术方案》B3.2 一致。**键路径必须是 `general.designResolution`**——写在顶层 `designResolution` 不生效（已踩实）。

**素材为什么全走 Bundle 路径加载**：非 `resources/`、非 Bundle 目录的资源**不支持按路径加载**，而手写场景里的 uuid 资产引用是这套流程里最容易写错的一环。把两批素材都配成 Bundle 后，场景只留结构、取图全在代码里，可脚本化复现。**代价见 §7.4**。

## 5. 踩过的坑（都付过学费，别再踩）

**① 脚本组件的 `__type__` 用 class id，不是 `.meta` 的 uuid。**
手写场景时把 `Boot.ts.meta` 里的 uuid 填进 `__type__`，构建报：
`Missing class: 9f249a5a-…` / `Script "…" attached to "Canvas" in scene "Boot" is missing or invalid`。
真实类型名是**编译期压缩出的 class id**（本例 `9f249paOe5Ad45gB9l98vaP`），可在一次构建后从
`assets/main/index.js` 里用 `_RF.push\{\},"([^"]+)","([^"]+)"` 读出来。它是 uuid 的确定性压缩形式，
所以「先构建一次拿 id、再接场景」是可行流程。

**② 用错文件判断"脚本没编译"。**
最初只在 `src/chunks/bundle.js` 里找代码，找不到就下了"构建真失败"的结论。实际工程脚本在
`assets/main/index.js`。**结论前先把搜索范围铺满产物**。

**③ `SIGTERM in task build-script` / 退出码 36 是噪音。**
同一份日志随后即 `run build task 打包脚本 success`。它是编译子进程收尾时被杀的信号。
`m04_build.py` 因此不静默放过、也不误报失败，只提示去核对产物。

**④ 浏览器有 CORS，微信小游戏运行时没有。**
`Boot.ts` 用 `XMLHttpRequest`（构建产物的 adapter 在小游戏里把它映射到 `wx.request`，故**真机/模拟器不受 CORS 约束**）。
但走 web-desktop 验证时是真正的浏览器 XHR，会先发 OPTIONS 预检——服务端必须带
`MALL_ALLOWED_ORIGINS=<页面来源>`，否则 `Access-Control-Allow-Origin` 缺失、请求被浏览器拦掉，
客户端表现为 `ApiError: NETWORK (HTTP 0)`。**这是环境差异，不是代码 bug**。

**⑤ 端口被旧进程占着会让"改了配置没生效"变成假象。**
本次第一次 CORS 失败，真实原因是旧后端进程仍在监听 18081，新起的那个 bind 失败直接退出，
而 `/healthz` 探活返回 200 让人误以为新配置生效了。**重启服务后要用日志确认它真的起来了**
（`local development server started`），不能只看端口有响应。

**⑥ 运行时 `new Material()` 建出来的材质，`USE_TEXTURE` 默认是 0。**
`Material.initialize({effectAsset})` 不传 `defines` 时，引擎按"默认全为 0"处理（见引擎
`cocos/asset/assets/material.ts` 的 `IMaterialInfo.defines` 注释）。照抄 `builtin-sprite` 写的
自定义 effect 里有 `#if USE_TEXTURE` 分支，宏为 0 就走不采图的那条——**表现是精灵变成纯色块**
（实测铺位变灰块 / 白块）。正解：`mat.initialize({ effectAsset, defines: { USE_TEXTURE: true } })`。
⚠️ 中途试过的"把 `#if` 分支删掉、恒定采样"是**错路**：那样整条 pass 编译不过，连累同批精灵全部消失，
画面只剩文字。别照那条走。

**⑦ 手写场景里一个组件被两个节点引用，切场景时才炸。**
`Boot.scene` 的 `Canvas._components` 多列了一个下标 17，而那个 UITransform 的 `node` 指向 `Status`
节点——同一组件挂在两个节点上。Boot 作为唯一场景从不被销毁，所以这个错误一直没露头；
接上 `director.loadScene` 后，卸载 Boot 时该对象被销毁两次，控制台报
**`Error 5000`（`core/data/object.ts:372`，"重复销毁对象"）**。删掉那条多余引用后消失。
教训：手写 `.scene` 时 `_components` 的下标必须与组件自己的 `node` 字段一一对应，
构建通过 ≠ 引用正确。

**⑧ 在 `start()` 里同步 `loadScene` 也要避开。**
本项目的 Boot 改成 `this.scheduleOnce(..., 0.2)` 后再切——顺带给了 Boot 一屏最短可见时间。

### 7.4 Bundle 会把整个文件夹导出，不看引用（本轮新测出的事实）

配成 Bundle 后，**文件夹内的每个文件都会进包**，与"未被场景引用的资源不进包"这条对 `main` bundle 成立的规律**相反**。实测两次：

| 状态 | 主包合计 |
| --- | --- |
| 只 `mall_art`（13 件占位图） | 2170.8 KiB（53.0%） |
| 再加 `ui_main`（bg/ui/ico/state 全量 778 KiB） | 2948.7 KiB（72.0%） |

### 7.5 纹理压缩待办的前置

接界面引用图片**之前**必须先配好压缩，否则进包的是无损源图。落地时注意两点：① 只配 ASTC 会在开发者工具里看不到画面（平台不支持该格式解码），必须同时留 PNG/JPG 默认图；② 默认图是构建产物、**随包并计入主包**（`平台事实核对` §1.1.2），所以主包那张 ≈1712 KiB 的 ASTC 还要叠加默认图的成本，背景这类不透明大图优先降成 JPEG。
