## 5. 踩过的坑（都付过学费，别再踩）

**① 脚本组件的 `__type__` 用 class id，不是 `.meta` 的 uuid。**
手写场景时把 `Boot.ts.meta` 里的 uuid 填进 `__type__`，构建报：
`Missing class: 9f249a5a-…` / `Script "…" attached to "Canvas" in scene "Boot" is missing or invalid`。
真实类型名是**编译期压缩出的 class id**（本例 `9f249paOe5Ad45gB9l98vaP`），可在一次构建后从
`assets/main/index.js` 里用 `_RF.push\{\},"([^"]+)","([^"]+)"` 读出来。它是 uuid 的确定性压缩形式，
所以「先构建一次拿 id、再接场景」是可行流程。

**② 用错文件判断"脚本没编译"。**
最初只在 `src/chunks/bundle.js` 里找代码，找不到就下了"构建真失败"的结论。实际工程脚本在
`assets/main/index.js`。**结论前先把搜索范围铺满产物**。

**③ `SIGTERM in task build-script` / 退出码 36 是噪音。**
同一份日志随后即 `run build task 打包脚本 success`。它是编译子进程收尾时被杀的信号。
`m04_build.py` 因此不静默放过、也不误报失败，只提示去核对产物。

**④ 浏览器有 CORS，微信小游戏运行时没有。**
`Boot.ts` 用 `XMLHttpRequest`（构建产物的 adapter 在小游戏里把它映射到 `wx.request`，故**真机/模拟器不受 CORS 约束**）。
但走 web-desktop 验证时是真正的浏览器 XHR，会先发 OPTIONS 预检——服务端必须带
`MALL_ALLOWED_ORIGINS=<页面来源>`，否则 `Access-Control-Allow-Origin` 缺失、请求被浏览器拦掉，
客户端表现为 `ApiError: NETWORK (HTTP 0)`。**这是环境差异，不是代码 bug**。

**⑤ 端口被旧进程占着会让"改了配置没生效"变成假象。**
本次第一次 CORS 失败，真实原因是旧后端进程仍在监听 18081，新起的那个 bind 失败直接退出，
而 `/healthz` 探活返回 200 让人误以为新配置生效了。**重启服务后要用日志确认它真的起来了**
（`local development server started`），不能只看端口有响应。
