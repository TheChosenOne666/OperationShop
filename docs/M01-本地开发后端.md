# M01 本地开发后端

> 状态：已完成（后端接口 + 单元测试 + 端到端联调）
> 最后更新：2026-09-14

## 一、模块范围

M01 只交付「本机可以跑通的服务端权威闭环」，不包含微信登录、多账号、云端部署和游戏客户端。

包含：

- 两层五店的固定布局与每店单客收益规则，全部来自配置文件并做强校验。
- 开店（准备）与客流结算：店铺准备后才开始接待客人，收益一律由服务端按服务器时间计算。
- 单账号存档：原子替换落盘、重启接着算、损坏存档拒绝启动而不是静默重置。
- 仅本机可访问的 HTTP 接口，含来源白名单、Bearer 令牌、请求体限制与访问日志。

不包含（留给后续模块）：微信小游戏客户端与登录票据校验、好友/排行/互访/广告、布局调整与装修、多账号与云端存储。

## 二、运行方式

环境变量（前四项必填，缺失或非法一律拒绝启动）：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `MALL_LISTEN_ADDR` | 是 | 必须是显式回环地址加端口，例如 `127.0.0.1:8080`；填 `0.0.0.0` 会被拒绝 |
| `MALL_CONFIG_PATH` | 是 | 规则配置文件路径，开发用 `config/development.json` |
| `MALL_DATA_PATH` | 是 | 单账号存档文件路径，用临时目录以免污染工作副本 |
| `MALL_DEV_TOKEN` | 是 | 本地开发令牌，至少 32 字符 |
| `MALL_ALLOWED_ORIGINS` | 否 | 逗号分隔的浏览器来源白名单；留空表示不放开任何浏览器来源 |

启动与自检：

```bash
go build -o /tmp/server.exe ./cmd/server
MALL_LISTEN_ADDR=127.0.0.1:8080 \
MALL_CONFIG_PATH=config/development.json \
MALL_DATA_PATH=/tmp/mall/data.json \
MALL_DEV_TOKEN=local-development-token-0123456789 \
MALL_ALLOWED_ORIGINS=http://127.0.0.1:7456 \
/tmp/server.exe
```

## 三、接口清单

除健康检查外，所有接口都需要 `Authorization: Bearer <MALL_DEV_TOKEN>`；带 `Origin` 头时必须命中白名单。

| 方法 | 路径 | 入参 | 出参 |
| --- | --- | --- | --- |
| GET | `/healthz` | 无（免令牌） | `{status, mode, wechatLogin}` |
| GET | `/api/v1/config` | 无 | 规则配置（版本、初始金币、日客流、结算间隔、时区、五店收益表） |
| GET | `/api/v1/mall` | 无 | 当前存档快照，不结算、不刷新日期 |
| POST | `/api/v1/shops/{id}/prepare` | 空 JSON 对象 `{}` | 一次原子操作结果 |
| POST | `/api/v1/mall/settle` | 空 JSON 对象 `{}` | 一次原子操作结果 |

命令接口不接受任何客户端数据，只接受 `{}`；金币、时间、客流都由服务端产生。返回体结构：

```json
{ "state": { ... }, "earnedCoins": 12, "visitorsUsed": 2, "changed": true }
```

`changed=false` 表示本次请求没有产生任何状态变化（例如重复开店、同一时刻重复结算）。

错误码：

| HTTP | code | 触发条件 |
| --- | --- | --- |
| 400 | `INVALID_COMMAND` | 请求体不是空 JSON 对象（例如客户端塞入金币/时间/客流） |
| 401 | `UNAUTHORIZED` | 缺少或错误的 Bearer 令牌 |
| 403 | `LOCAL_ONLY` | 主机头或来源地址不是本机回环地址 |
| 403 | `ORIGIN_DENIED` | 浏览器来源不在白名单内 |
| 404 | `SHOP_NOT_FOUND` | 店铺 ID 未知，且不产生任何副作用 |
| 409 | `CLOCK_BACKWARDS` | 服务器时钟回退，暂不结算 |
| 409 | `NUMERIC_LIMIT` | 存档触及安全整数上限，拒绝写入部分结果 |
| 413 | `BODY_TOO_LARGE` | 请求体超过 1 KiB |
| 415 | `JSON_REQUIRED` | 请求类型不是 `application/json` |
| 500 | `SAVE_FAILED` | 存档写入失败，本次操作整体回滚 |

## 四、当前规则参数（开发期，非最终数值平衡）

| 参数 | 值 |
| --- | --- |
| 规则版本 | `m01-prototype-v1` |
| 初始金币 | 1280 |
| 每日客流 | 50 |
| 结算间隔 | 5 秒 |
| 业务时区 | `Asia/Shanghai` |

店铺与收益（顺序即客流轮询顺序）：

| ID | 店名 | 楼层 | 店位 | 单客收益 |
| --- | --- | --- | --- | --- |
| clothing | 衣橱 | 2 | 1 | 12 |
| dessert | 甜屋 | 2 | 2 | 8 |
| bookstore | 书店 | 2 | 3 | 10 |
| coffee | 咖啡 | 1 | 1 | 6 |
| flowers | 花束 | 1 | 2 | 9 |

轮询按上表顺序在「已准备」的店铺间循环，一轮五客共 45 币。子窗口内的客流时间不浪费：不足一个间隔的余量会结转到下次请求。跨业务日只补当天客流，不追补历史离线收益。

规则指纹随配置内容变化；配置一旦改动，旧存档会被拒绝加载而不是被覆盖。

## 六、测试策略

- `internal/game`：配置校验与严格 JSON、存档原子替换与损坏拒绝、结算时序（间隔余量、轮询顺序、客流耗尽、跨日刷新、时钟回退、保存失败回滚、安全整数上限）、并发准备与结算幂等、返回值与内部切片的隔离。
- `internal/api`：处理器构造参数校验、本机限定、Bearer 认证、来源白名单与预检、命令路由的幂等与错误映射、请求体类型与大小限制、无效路由、访问日志不泄露令牌、并发命令只提交一次。
- 端到端：编译真实二进制，用真实端口和真实存档文件逐条打接口，覆盖单测无法覆盖的进程启动与信号处理路径。

## 七、已知边界与待办

- `cmd/server` 没有单元测试，靠端到端联调覆盖；`run()` 内的环境变量与信号处理未做参数化，后续如需单测需先拆出依赖注入。
- 令牌认证只用于本机开发；接入微信小游戏时必须替换为真正的登录票据校验。
- 存档为单文件单进程设计，多实例部署需要换成外部存储。
- 尚未接入客户端，接口契约目前只由服务端测试保证。
- 浏览器来源白名单为精确字符串匹配，主机名大小写不敏感的问题未处理（浏览器实际发送小写主机名）。
