## 0. 一句话概念与玩家动词

**一句话**：一间开在街角的两层小商场，你每天来看一眼，花一点金币让它比昨天好一点点，然后关掉——没有倒计时、没有被催、也不会因为你不在而变差。

### 0.1 动词优先法（Player Verbs）

先问"玩家在这个游戏里做的是哪几个动词"，再问"这些动词支撑哪种情绪"。本作的动词集合**刻意极小**，这是设计选择而不是内容不足：

| 动词 | 玩家实际做的事 | 频率 | 情绪目标 |
| --- | --- | --- | --- |
| **看** | 读取"今天客流多少、金币多少、哪家能开" | 每次进入，1 秒内 | 心里有底（无威胁感） |
| **开** | 把一家铺位从"空铺"变成"营业中" | 低（一次性） | "我又多了一点" |
| **解锁** | 花金币把二层空铺位变成可用铺位 | 极低（一辈子 3 次） | 里程碑式进展 |
| **升级** | 花金币提高某家店的单客收益 | 低（累计 20 次封顶） | 渐进式变好 |
| **比** | 看自己与好友的经营名次 | 低 | 轻社交在场感，不是胜负 |

**关键判断**：本作**没有"战斗/躲避/争夺/经营调度"这类高频动词**。玩家的核心动作是**低频、主动、不可逆的"花费决策"**，中间用固定节奏的客流被动填充。因此这不是一款"操作型经营"，而是一款**"决策 + 观察"型治愈经营**。这个概念定位决定了后面所有取舍：

- 因为高频动词缺失，**节奏必须靠"每日客流上限"提供结构**（见 §4）；
- 因为决策低频，**每次决策必须看得懂且无后悔风险**（见支柱 P2 / P1）；
- 因为核心是"花费决策"，**金币的出口设计就是玩法本身**（见支柱 P3）。

## 1. 设计支柱（Design Pillars）

四条支柱，按冲突时的优先级排序。每条支柱都给出**"它成立时我们会拒绝什么"**——不能用来裁决取舍的原则，不算支柱。

### P1 · 零负债：没有任何一次打开是"来救火"的

> **宗旨**：玩家的每一次打开都是纯收益。不看不会亏，离开不会亏，做错也不会亏。

**它成立时，我们会拒绝：**
- 任何**倒计时强回访**设计：收菜提醒、限时活动、"离线收益要看广告翻倍"、体力/钥匙恢复。
- 任何**离线惩罚或衰减**：断签、连续登录中断清零、资源过期作废、排名因不活跃下滑。
- 任何**失败态**：破产、倒闭、客流差评、负债、被降级。玩家唯一的"代价"是**进度慢一点**。
- 任何**需要预留注意力**的设计：挂机盯着、抢时间窗、错过就永久失去的机会。

**现状对齐**：✅ 与需求文档第三节原则 1/3、草案 A6、以及用户 2026-09-14 锁定的"无失败态"一致。

### P2 · 一屏看懂，两击做完：把决策成本压到最低

> **宗旨**：玩家进入后第一眼就知道"我现在能做什么"，用不超过两次点击完成一件事。

**它成立时，我们会拒绝：**
- 需要**进二级页面才能看懂当前状态**的设计（主界面必须自证状态）。
- **第三个常驻数字 / 第二种货币 / 多层资源**。屏幕上永远只有 **金币** 与 **客流** 两个数字。
- **嵌套菜单、翻页列表、需要滚动才看得完的信息架构**。
- 需要玩家**先学一套系统再看懂数值**的设计（如百分比加成、复合公式外显）。

**现状对齐**：✅ 与需求文档第三节原则 4/5/6（一屏看完、数字克制、一屏一意图）一致。

### P3 · 慢慢变好，而且看得见：金币有出有进，进展可视化

> **宗旨**：这是一款"增长"游戏。增长的每一分投入，都要看得见回报，且**永远不存在"投了反而更差"**。

**它成立时，我们会拒绝：**
- 任何**反向激励**：投入金币后日均收益反而下降的机制（例如固定客流下解锁低价店会摊薄收益）。
- 任何**只涨数字、场景不变**的"看不见的增长"（升级若只有数值变化，则违反本支柱）。
- 任何**归零 / 重置 / 亏损**机制。
- 任何**金币只进不出**的状态（缺少出口会让"经营"退化为"数字堆积"）。

**现状对齐**：⚠️ 部分对齐（2026-09-14 复核）。金币两个出口（解锁 + 升级）、客流随店铺增长（消除反向激励）两条已满足；"**升级是否可见**"的缺口已于同日拍板补齐——升级设四级可见回报（Lv2 橱窗暖光 / Lv3 招牌小彩灯 / Lv4 门口花箱 / Lv5 招牌描金，见草案 A3）。**唯一残留缺口**：全部铺位解锁且全部店铺满级后，金币不再有出口（总投入约 23600）——已确认为 v1 **已知缺口**，第一版不做长期出口，见 §7.1。

### P4 · 克制的在场感：不催、不推、不攀比

> **宗旨**：社交与商业都只提供"陪伴"，不生产"义务"和"压力"。

**它成立时，我们会拒绝：**
- **广告**（第一版任何形式的广告都不接）。
- **生产社交义务的设计**：互访、互助、留言、送礼、"帮好友点一下"、"不帮就落后"。
- **羞辱性榜单**：显示"你输了"、显示掉名次提醒、用红色标注落后、把排行榜做成胜负。
- **推送/弹窗催促**：召回提醒、"你已三天未登录"。

**现状对齐**：✅ 与需求文档 4.6、第九节、草案 A7、用户锁定的"好友只做经营排行榜""第一版不接广告"一致。

> **支柱漂移风险（先标注）**：P3 与 P4 都依赖"内容载体"，而第一版明确**不做装修换肤、不做互访留言**，导致 **Expression（表达）与 Fellowship（陪伴）两种美学目前几乎没有载体**。这是本作最需要盯住的长期风险：若后续版本迟迟不给载体，游戏会从"治愈经营"退化成"纯数值增长器"，P3 名存实亡。已写入 §7 待确认项（其中"升级可见回报"的缺口已于 2026-09-14 补齐；Expression / Fellowship 的载体缺口仍留待后续版本，见 §5.4）。

## 2. MDA 分析

MDA（Mechanics → Dynamics → Aesthetics）的核心是"设计者造机制，玩家体验美学"。下面三层自上而下推导、自下而上验证。

### 2.1 机制层 Mechanics（规则本身）

| 机制 | 内容 | 来源 |
| --- | --- | --- |
| 铺位结构 | 两层共 5 铺位，铺位↔店铺一对一固定绑定 | 需求 4.1 |
| 解锁 | 二层 3 铺位从左到右依次花金币解锁 | 需求 4.1 / 草案 A2 |
| 开店 | 每家店二元状态（待开业 / 营业中），开业才接待客人；**第一版不设手动关店**（2026-09-14 拍板） | 需求 4.2 |
| 客流节奏 | 固定间隔到店（初版 5 秒一位），按**一层临街优先**顺序轮转（咖啡→花束→衣橱→甜屋→书店）并跳过未开业店铺 | 需求 4.3 / 草案 A4 |
| 每日客流上限 | 基础 20 + 每已开业店 ×15；**当天首次产生客人时冻结为当日值**（0 店不冻结）；当日新开店次日生效 | 需求 4.3 / 草案 A4 |
| 单客收益 | `单客收益 = 该店当前等级单价 + 该层满铺加成(0 或 1)` | 需求 4.4 / 草案 A3 |
| 店铺等级 | 每店 1–5 级，升级提高单价，历史收益不追溯 | 需求 4.4 |
| 满铺搭配 | 同层全部"已解锁且已开业"→ 该层所有店单价 +1（固定加值） | 需求 4.5 / 草案 A3 |
| 金币出口 | 仅两个：解锁铺位（一次性）、升级店铺 | 需求 4.4 |
| 业务日 | 按 `Asia/Shanghai` 0 点切分，跨日刷新客流、不动累计 | 需求 4.7 / 草案 A6 |
| 离线 | 不补历史客流、不扣任何东西 | 需求 4.3 / 草案 A6 |
| 结算权威 | 一切数值由服务端计算，客户端只展示 | 需求 4.3 / M01 |
| 排行榜 | 只读，按金币排序 | 需求 4.6 / 草案 A7 |

### 2.2 动态层 Dynamics（机制在玩家手里涌现出的行为）

| 涌现动态 | 由哪些机制共同产生 | 是"想要"还是"要防" |
| --- | --- | --- |
| **短会话习惯**：每天来一次、点一两下就走 | 每日客流上限 + 无倒计时 + 无签到 | ✅ 想要。这是"低压力"的行为证据 |
| **解锁与升级的排序**：金币只有一份时，先解锁新铺位还是先升级现有店 | 解锁成本 vs 升级成本 | ✅ 想要（原"凑满一层 vs 上二层"的取舍已于 2026-09-14 判定不成立，改判为本条，见附录 A.2 冲突二） |
| **升级排序的边际计算**：先升哪家店最划算 | 等级单价表 + 升级成本 + 回本天数 | ✅ 想要。这是本作唯一的"策略深度" |
| ~~**关店试探**：关掉一家看加成消失~~ | — | ❌ **已消除**（2026-09-14）：手动关店已移除，此动态不再可能出现，见附录 A.2 冲突一 |
| **无焦虑回归**：三天不来，数据如常，不被追问 | 离线不补不扣 + 不弹召回 | ✅ 想要。P1 的直接体验验证 |
| **只读旁观**：看看好友名次，不产生互动义务 | 只读排行榜 | ✅ 想要。P4 的社交边界 |
| **盯屏等待**：停留时每 5 秒等一次结算 | 5 秒结算轮询 | ⚠️ 要防。与"不用盯屏"拧（见附录 A.2 冲突三） |
| **后期无脑**：全解锁全满级后金币无处可花、无新决策 | 出口封顶 + 无后续内容 | ⚠️ 要防。**已确认为 v1 已知缺口**（2026-09-14）：第一版不做长期出口、显式记录不掩盖，见 §7.1 |

### 2.3 美学层 Aesthetics（玩家感受到的情绪）

按重要度排序：

| 位次 | 美学（借用常见 8 类） | 在本作的载体 | 强度 |
| --- | --- | --- | --- |
| 1 | **Relaxation（放松）** | 无倒计时、无失败、暖色治愈视觉、固定温柔节奏 | 强 |
| 2 | **Progression（成长 / 变好）** | 解锁铺位、升级店铺（四级可见回报）、金币增长、"我又大了一点" | 中 |
| 3 | **Fellowship（陪伴 / 社群）** | 只读经营排行、"有好友也在玩"的在场感 | 弱 |
| 4 | **Discovery（发现）** | 解锁新店开张的新鲜感（5 种品类固定，无随机） | 弱 |
| 5 | **Expression（表达）** | （v1 几乎没有载体——不装修、不换肤、不布局） | 极弱 |

**最重要的两种：Relaxation（第一）+ Progression（第二）。**
**为了保住它们，我们主动放弃：**
- 为 Discovery 强加**随机性**（随机事件、抽卡、roguelike 关卡）——随机性会带来"可能变差"的预期，与 P1 无失败、P3 无反向激励冲突；
- 为 Expression 强加**自由度**（装修、换肤、自由布局）——第一版成本不划算，且自由编辑会把"看一眼就走"变成"要花时间搭"，与 P2 冲突；
- 为 Fellowship 强加**互动**（互访、互助、留言）——互动会生产社交义务，与 P4 冲突；
- 所有**紧张型美学**（Challenge 挑战、Competition 竞争胜负、Sensation 刺激）——它们与 Relaxation 直接互斥。

> **结论**：这是一款"以 Relaxation 为骨、Progression 为肉"的游戏。它的美学天花板不在"更多内容"，而在"**节奏与视觉的稳定**"。任何增加紧张感的提案，默认否决。

## 3. 玩家心理映射

### 3.1 自我决定论（SDT）：三个基本心理需求

| 需求 | 由哪个具体机制满足 | 说明 |
| --- | --- | --- |
| **自主 Autonomy** | 无签到、无每日任务、无强制回访；"何时来、做多少、先解锁哪家、先升哪家、要不要把已解锁的店开起来"全部由玩家决定 | 玩家是"我想来"，不是"我不得不来"。这是本作最强的 SDT 支撑点 |
| **胜任 Competence** | 能看懂并做出划算的取舍（解锁新店 vs 升级旧店；升级回本判断）+ 可见进展（空铺变满、等级提升、金币上涨） | ⚠️ 本作的"胜任"是"**我在变强**"而非"**我赢了**"。因为无失败态，不提供"克服困难"的胜任感——这是刻意选择，不是缺陷 |
| **关联 Relatedness** | 只读经营排行榜（好友也在玩）；场景里的客人、店长、栏杆上的橘猫提供的拟社会陪伴 | ⚠️ 弱。第一版刻意不做互访互助，把"关联"压在"看得到但不打扰"的强度上 |

> **设计含义**：SDT 三需求中，本作把**自主**做到最强、**胜任**做成"温和增长型"、**关联**刻意做弱且克制。谁想加强"关联"（加互访/互助），必须先推翻 P4，需要用户拍板。

### 3.2 Bartle 玩家类型定位

| 类型 | 是否目标受众 | 判断依据 |
| --- | --- | --- |
| **Achiever（成就者）** | ✅ **主力受众** | 为"解锁全部铺位、升满店铺、金币变多"而玩。本作给了清晰、无风险、可累积的目标阶梯 |
| **Socializer（社交者）** | ✅ **次要受众（轻社交版）** | 为"看看好友名次、有共同话题"而玩；但本作**不给互动工具**，所以只承接"轻社交者"，不承接"重度社交者" |
| **Explorer（探索者）** | ❌ 明确不是 | 没有隐藏地图、没有系统深度、没有可挖掘的秘密。5 种店铺固定，Discovery 极浅 |
| **Killer（杀手）** | ❌ 明确不是 | 无 PvP、无胜负、榜单不做羞辱性设计。Killer 会在这里找不到任何乐趣 |

> **Bartle 的用法**：本作的真实核心画像**溢出了四象限**——它服务的是 **"Cozy / 治愈系经营"受众**（与需求 2.1 的"25–40 岁、碎片时间、喜欢整洁治愈视觉、反感被催被弹窗被排行榜羞辱"高度一致）。因此 **Bartle 在本项目里做"排除法"比做"定位"更有价值**：它帮我们明确说清"不服务谁"（不服务求挑战的 Killer、求深度的 Explorer），从而在概念期就砍掉不该长出来的分支。

## 4. 心流平衡

本作没有"挑战"，因此不能套用"挑战与技能匹配"的传统心流模型。这里的心流需要**重新定义**。

### 4.1 本作的心流是"低唤醒放松型心流"

- 传统心流：靠难度爬升维持注意力；
- 本作心流：靠**稳定的预期 + 温和的成长 + 零威胁**维持。玩家的理想状态是"平静地看着它慢慢变好"，而不是"紧张地应对变强"。
- 因此，**所有会制造紧张的手段（倒计时、衰减、竞争、随机损失）都必须拒绝**——它们会把"放松心流"打断成"紧张心流"。

### 4.2 每日客流上限 = 天然的心流收束点（本节重点）

这是本作**最重要的一处节奏设计**，必须论述清楚：

- 本作没有"关卡结束""Boss""回合"，如果不设边界，玩家会陷入**"永远做不完"或"无脑挂机"**两个坏结局。
- **每日客流上限**（如开局 50）在固定到店间隔（5 秒/位）下，意味着"**今天的客流大约 4–5 分钟走完**"。于是每一天天然有一个**收束点**：客流耗尽 → 今日收益停止 → 玩家得到一个明确的"今天做完就可以停"的信号。
- 这个收束点同时解决三件事：
  1. **防无限挂机**：不会因为"再多看一会儿就多赚"而把放松变成无聊的等待；
  2. **防进度焦虑**：不会因为"永远赚不完、永远追不上"而产生负债感（与 P1 一致）；
  3. **给出节奏感**：每天开门营业 → 客流走完打烊 → 次日重新开张，形成"日常"（daily rhythm），这正是 Cozy 类游戏的核心节拍。
- **设计红线**：任何会破坏这个收束点的东西（永不耗尽、收益随时间衰减、"错过今天损失客流"）都要否决。

### 4.3 难度曲线 = 消费曲线的斜率

- 本作没有"越来越强的敌人"，但有**越来越大的消费规模**：从开局日入约 375，到二层全解锁约 950，再到五店满级约 1672（草案 A5）。
- "成长感"来自**投入 → 回报 → 更大投入**的正向循环，且每一档解锁都有明确增量（草案 A4 的反向激励推演已保证这一点）。
- 曲线设计**不要求玩家追平**（满级 21000 金币属长线，明确"不要求达成"）——这保护了 P1：追不上也不会有惩罚。

### 4.4 已知的心流断裂点（需盯住）

| 断裂点 | 触发条件 | 影响 | 处置 |
| --- | --- | --- | --- |
| **后期无脑期** | 全铺位解锁 + 店铺满级后，金币只进不出、无新决策 | 心流中断（没有目标也没有选择） | **已确认为 v1 已知缺口**（2026-09-14）：第一版不做长期出口，留待后续版本设计，见 §7.1 |
| **等待观感** | 玩家停留盯着看，每 5 秒跳一次 | "在等它"而非"已经做完" | 表现层不要把等待可视化（不做进度条催促），收益用柔和补间（见附录 A.2 冲突三） |
| **节奏过慢** | 后期客流 95 时，走完约 8 分钟 | 若盯着看会觉得慢 | 设计上鼓励"不看"，但需实机确认"看着也不难受"（数值层，Phase 2 处理） |

## 5. 范围分层

四层范围：**核心循环 → 最小可玩 → 第一版 → 后续版本**。每层写清"包含什么"和"**明确排除什么**"。

### 5.1 核心循环（Core Loop）——删掉任何一环，玩法不成立

```
打开游戏
  → 一眼看到今天的客流与金币          （看）
  → 做一次主动花费决策（开店/解锁/升级）  （开/解锁/升级）
  → 客人按固定节奏到店，金币缓慢增长      （被动填充）
  → 当日客流耗尽，收益停在当天上限        （每日收束点 ★）
  → 次日 0 点客流恢复，回到第一步         （daily rhythm）
```

- **必须包含**：5 个动词（看/开/解锁/升级/比）、每日客流上限与收束、服务端权威结算。
- **明确排除**：任何形式的失败态、任何倒计时催回、任何随机事件。
- **本层是一切的根。** 后续每一层都只能"加厚"，不能"改变"这五步的性质。

### 5.2 最小可玩（Minimum Playable）——验证"低压力经营是否成立"的最小版本

用于**最早验证概念**，可以没有美术精度、没有动画。

- 包含：两层五铺位（含二层逐店解锁）；**开店**（第一版不设手动关店，2026-09-14 拍板）；固定节奏客流 + 每日上限；单客收益（等级单价）；金币两个出口（解锁 + 升级 1–5 级）；**一层满铺加成**（只验证一条搭配规则）；主界面 HUD（金币 / 客流 / 三入口）；服务端权威结算；存档持久化。
- **明确排除**：好友排行、任何弹窗、任何客人走动/金币飘字动画（数字直接跳变即可）、第二层满铺加成、新手引导、离线提示。
- 验证目标：玩家能否"看懂状态 + 完成一次决策 + 感到放松"。

### 5.3 第一版（v1）——可上线的完整范围

= 5.2 最小可玩 **+** 以下：

- **全部 5 家店 + 两层满铺加成**（一层 2/2 与二层 3/3 各自生效）；
- **好友经营排行榜**（只读、按金币、无好友时显示自己）；
- **表现层**：客人从入口走到目标店、金币飘字、数字滚动补间、店铺状态区别（未解锁 / 已解锁未开业 / 已开业）；
- **断线重连与错误提示**（失败可理解，不静默丢数据）；
- **首次进入的新手引导**（P2，尽量有）与**离线状态提示**（P2，尽量有）。

**明确排除（与需求文档第九节一致，概念层再确认一次）**：
- ❌ 广告（任何形式）
- ❌ 好友互访 / 互助 / 留言 / 送礼
- ❌ 装修换肤 / 店铺换位 / 布局调整 / 店铺内部视角
- ❌ 新楼层 / 新店铺品类
- ❌ 签到 / 任务 / 成就 / 连续登录奖励
- ❌ 多货币 / 第二资源 / 体力钥匙
- ❌ 随机事件 / 抽卡
- ❌ 员工 / 宠物系统
- ❌ 真实货币支付

### 5.4 后续版本（Beyond v1）——只列方向，**不承诺**

按 P3/P4 的载体缺口排序：

| 方向 | 补哪种美学 | 依赖 |
| --- | --- | --- |

### A.2 与设计支柱冲突 / 需要改（逐条指出）

**冲突一 · 「关店」缺少目的，与 P1 相违** ✅ **已决议（2026-09-14）**
- 位置：需求 4.2、草案 A2/A3。
- 问题：在无损耗、且满铺加成鼓励"全开业"的结构下，关店会同时失去该店的客流与同层 +1 加成，是**纯负收益**动作。玩家没有任何理性理由关店。一个"只能变差"的按钮，既违背 P1（无失败态——不给自伤入口），也违背 P2（低决策成本——增加一个无意义的决定）。
- **决议**：v1 **移除手动关店入口**（铺位只有 未开放 / 待开业 / 营业中 三态）。曾考虑的备选"每日营业开关"**不采用**。（原"待确认项 1"结案。）

**冲突二 · 满铺加成与"客流随店增长"叠加，削弱了"凑满一层"的取舍张力** ✅ **已决议（2026-09-14）**
- 位置：需求 4.5（满铺加成是为了制造"凑满一层 vs 上二层"的取舍）vs 草案 A4（客流上限随每店 +15）。
- 问题：每多开一家店，**既多了客源（+15 客流）又（同层满时）多了单价（+1）**，"要不要开这家店"几乎总是"要"。取舍张力被冲淡——这与需求 4.5 的设计**意图**存在张力（虽不是数值错误，反而消除了反向激励）。
- 澄清：真正有取舍的地方只剩"**解锁与升级的先后排序**"（600 解锁衣橱 vs 300 升花束的先后），而不是"开/不开店"。
- **决议**：把"取舍"的实现位置**显式改写**为"**解锁 / 升级的资源分配排序**"，以需求 4.5 的修正口径为准，并在 Phase 2 经济系统 GDD（G5）里作为验收口径。（原"待确认项 2"结案。）
- ⚠️ **遗留（转 G5）**：按当前初版数值，解锁的回本期（3–7 天）全面优于升级（约 12 天），"解锁 vs 升级"的**取舍在数值上仍未成立**——属数值定稿问题，已下沉 G5，不在概念层解决（见 `design/gdd/系统-经营与成长.md` 附录 A 冲突②）。

**冲突三 · 「5 秒轮询结算」的观感与"不用盯屏"拧（美学实现风险）**
- 位置：草案 B3.6（每 5 秒结算）。虽属技术层，但**后果落在美学层**。
- 问题：玩家停留盯着看时，界面每 5 秒跳一次数字，会形成"等待 / 检查"的观感，与"做完就走"的 Relaxation 略拧。
- 建议（概念层记为红线）：表现上**不要把等待可视化**（不做进度条/倒计时催促），收益变化用**柔和补间**而非闪烁。具体实现交程基岩。

**冲突四 · 满级长线目标缺少美学回报，与 P3 冲突** ✅ **已决议（2026-09-14）**
- 位置：草案 A5（五店满级 21000 金币，仅提高单客收益）。
- 问题：升级**只有数值变化，没有视觉变化**。到中后期，玩家的"慢慢变好"会变成**看不见的变好**（数字涨、商场不变），直接违反 P3"看得见"。这也是 Expression 美学几乎无载体的后果。
- **决议**：v1 **给"店铺升级"四级可见回报**（Lv2 橱窗暖光 / Lv3 招牌小彩灯 / Lv4 门口花箱 / Lv5 招牌描金；实现为 2 个新资产 + 3 个材质参数，视觉规格见《美术圣经》§7.7）。缺口已补齐，**不再**列为 v1 显式缺口。（原"待确认项 3"结案。）

### A.4 明确结论：A 部分是"一份合并大稿"，必须拆分

**结论**：《玩法与技术方案》A 部分（A1–A7）把**概念、玩法规则、数值、以及部分技术实现**揉在一份文档里，**不符合工作室 SOP**。按 SOP：

- **A 部分 → 拆成逐系统 GDD**（每系统八节：概述 / 机制 / 数据 / 公式 / 边缘情况 / UI 接口 / 依赖 / 验收标准）；
- **B 部分（B1–B7）→ 归程基岩**，进架构文档与 ADR；
- **三份主文档（需求 / 玩法与技术方案 / 开发规划）互相引用**，拆分后需同步更新引用关系（本项目已知的文档一致性约定）。

拆分不是重写——A 部分的规则内容**全部保留**，只是**重新分配到正确的文档层级**。

### A.5 系统拆解清单 + 依赖排序（Phase 2 输入）

**建议拆为 9 个逐系统 GDD（+1 个 P2 延后项）**，每个按八节撰写。

| 编号 | 系统（GDD 名） | 覆盖草案章节 | 核心内容 |
| --- | --- | --- | --- |
| **G1** | 铺位与解锁系统 | A2 | 两层五铺位结构、二层逐店解锁、铺位↔店铺一对一绑定、解锁确认 |
| **G2** | 店铺经营与升级系统 | A2/A3 | 开店（**第一版不设关店**，2026-09-14 拍板）、店铺等级 1–5、升级 |
| **G3** | 客流系统 | A4 | 到店节奏、轮转顺序、跳过未开业、每日上限、上限随店增长、**首次产生客人时冻结**、跨日刷新 |
| **G4** | 收益与结算系统 | A3 | 单客收益公式、等级单价、满铺加成、服务端权威结算、时间余量结转 |
| **G5** | 经济与平衡系统 | A5 | 金币产出曲线、两个出口的定价、回本天数、反向激励校验、无破产 |
| **G6** | 业务日与离线系统 | A6 | `Asia/Shanghai` 0 点切分、跨日刷新、不补离线、时钟回退拒绝 |
| **G7** | 好友经营排行榜系统 | A7 | 只读、按金币排序、无好友降级、授权受限时的降级（语义层） |
| **G8** | 主界面信息架构与 UX | A1 + 需求六节 | 一屏看完、三入口、两个数字、HUD 固定、"一屏一意图"、三页/弹窗的字段与流程 |
| **G9** | 表现与反馈系统 | 需求 R-12 | 客人走动、金币飘字、数字滚动、三种店铺状态差异（与客户端的接口契约） |
| **G10** | 新手引导与离线提示（**P2 延后**） | 需求 R-14/R-15 | 首次引导三步、离线状态提示（v1 尽量有，可后拆） |

**依赖排序（建议 Phase 2 撰写顺序）：**

```
第 0 层（全局底座，先写）
  G6 业务日与离线        ← 无内部依赖；所有系统的时间语义都依赖它
  G8 主界面 IA / UX      ← 可与 G1–G6 并行起；它定义"要显示什么"，
                            反过来约束 G1–G6 各自的「UI 接口」节

第 1 层
  G1 铺位与解锁          ← 定义"有哪些铺位、怎么解锁"

第 2 层（依赖 G1）
  G2 店铺经营与升级      ← 依赖 G1 的"已解锁"状态；定义"开业/等级"

第 3 层（依赖 G2）
  G3 客流                ← 依赖 G2 的"开业"状态（谁来接待客人）

第 4 层（依赖 G2 + G3）
  G4 收益与结算          ← 依赖 G2 的等级单价 + G3 的到店数 + G1 的满铺判定

第 5 层（收口，必须最后写）
  G5 经济与平衡          ← 汇总 G1/G2 的消耗价 + G4 的产出，做整体平衡校验

其后
  G7 好友排行榜          ← 依赖 G4/G5 对"金币"的定义
  G9 表现与反馈          ← 依赖 G3/G4 的"到店 / 收益"事件语义

P2
  G10 新手引导与离线提示
```

**依赖关系的两个要点**：
1. **G8（IA/UX）应尽早起**，与 G1–G6 并行。因为本作的红线是"一屏看懂"，界面约束应当**先于**系统细节确定——由 G8 定义"屏幕上要出现什么"，再反向约束每个系统的「UI 接口」节，避免系统做完才发现放不进一屏。
2. **G5（经济与平衡）必须最后写**。它是"汇总校验"型系统，只有 G1–G4 的数值都定了，才能做平衡与反向激励复核。它也是承接概念层 P3 与"反向激励推演表"的落点。

## 附录 B · 概念层红线清单（供 Phase 2 各 GDD 自查）

撰写／评审任何系统 GDD 时，凡命中以下任一条，即视为违反概念层，需回退：

1. 引入了"不登录就损失"的设计（断签、过期、掉名次惩罚）。→ 违反 P1
2. 引入了失败态（破产、倒闭、差评、负债、降级）。→ 违反 P1
3. 屏幕上出现第三个常驻数字，或第二种货币/资源。→ 违反 P2
4. 需要进二级页面才能看懂主界面当前状态。→ 违反 P2
5. 出现"投入后日收益反而下降"的机制。→ 违反 P3
6. 出现只有数值变化、场景无变化的"增长"。→ 违反 P3（需在 GDD 里给出可见回报或标注为缺口）
7. 出现金币只进不出的终态而无任何交代。→ 违反 P3（需在 G5 给出处理）
8. 引入任何形式的广告、或生产社交义务的互动（互访/互助/留言）。→ 违反 P4
9. 引入了紧张型美学（挑战、竞争胜负、倒计时、随机损失）。→ 违反 Relaxation 主美学
10. 加入了第一版明确排除的内容（装修/换肤、新楼层、签到任务成就、随机事件、员工宠物、真实支付）。→ 超出 v1 范围
