### 0.2 测量方法（可复现）

- **色值**：用 ffmpeg 将 JPG 解码为 RGB24 原始像素，再按 16 级量化统计**区域主色**（dominant color），并对关键点做 9×9 邻域均值。统计口径为"面积占比最高的量化色"，因此数值是**代表色**而非单像素真值。
- **比例**：对 `主界面图.jpg`（1080×1918）做逐行剖面（每 25px 一行，统计均值色 / 绿色像素占比 / 暗像素占比）与逐列剖面，据色带突变定位分区边界。
- **复核建议**：正式落地前，请美术在 Photoshop 中用吸管对下列 Hex 做一次人工校准（尤其是木色与奶白，JPG 有压缩噪声）。

## 1. 风格定位

### 1.1 一句话风格

> **暖木治愈的街角微缩景观（Cozy Golden-Hour Woodcraft）**——把一座两层小商场当成一只**木质微缩模型盒**，用**正视图平面构成**端到玩家面前：奶白墙、暖木框、低饱和暖绿雨棚，傍晚的暖光从橱窗里漫出来。

### 1.2 情绪目标

| 位次 | 情绪 | 本作视觉如何承载 | 对接概念层 |
| --- | --- | --- | --- |
| **主** | **Relaxation（放松）** | 低饱和 / 无紧张对比 / 暖光 / 无失败态视觉（不出现红字、感叹号、警告三角） | 概念 §2.3 第 1 位 |
| **次** | **Progression（变好）** | 空铺 → 有店 → 更亮的橱窗；等级提升要有可见变化（见 §7 四级可见性） | 概念 §2.3 第 2 位 |
| 弱 | Fellowship / Discovery | 橘猫、明信片、街上的客人——**在场感**，不是互动 | 概念 §2.3 第 3/4 位 |

**情绪词（视觉自检用）**：安静、干净、暖、慢、被照顾。
**反向情绪词（出现即判定偏离）**：热闹、促销、紧张、廉价、冷清、破败。

### 1.3 三条不可违背的风格红线

1. **正视图平面构成**：禁止等距 / 斜投影地图视角；禁止地面透视收敛（地面是**水平色带**，不是梯形）；楼层之间不做透视缩放，二层与一层同宽。
2. **暖调统一，暖绿是"暖色域内的绿"**：品牌绿取**黄相绿**（§2.2），不使用冷绿（如 `#2E6B4F` 一类的蓝相绿）。
3. **不做金属质感的光**（除黄铜壁灯、金币这类明确的金属小件）：木是木、布是布，禁止塑料高光与镜面反射。

## 2. 色彩体系

### 2.1 为什么"暖光但不高饱"（先立原则，再给色值）

竖屏小游戏、玩家每天停留 4–5 分钟盯着看、主美学是 Relaxation——这三条决定了饱和度必须被压住：

1. **饱和度 = 唤醒度**。高饱和暖色（如 `#FF6B2C`）在色彩心理学上是"促销 / 街市 / 紧迫"的信号，会直接破坏 Relaxation 主张的"低唤醒放松型心流"（概念 §4.1）。**要"暖"，不要"烈"**。
2. **底色过饱和会吃掉数值的可读性**。本作的红线是 P2「一屏看懂」，屏幕上只有两个数字。木纹 + 高饱和暖橙底会让深棕数字的对比度掉到 4.5:1 以下，与 §9 的可访问性下限冲突。
3. **长停留 + 小屏 = 视觉疲劳**。高饱和暖色在 5 分钟连续注视下会产生明显的色适应疲劳，玩家体感是"看久了眼睛累"，而不是"舒服"。
4. **暖光本身就是"被照顾"的信号**（傍晚家居灯的联想），一旦推高饱和就变成"商业热闹"，情绪从"被照顾"滑向"被推销"。

**定量约束**：主色域 HSB 饱和度 **S ≤ 45%**、明度 **V 60–85%**；仅**金币金（S ≈ 88%）**与**花色（S ≈ 55%）**允许突破，作为全画面仅有的两个高饱和锚点。

### 2.3 暖冷对比关系（冷色在暖色域内的角色）

- **暖色域占画面 ≈ 85%**（奶白 + 暖木 + 暖光 + 砖红），这是绝对主导，不可被稀释。
- 画面里**没有大面积冷色**。仅有的两个"非暖"元素承担**功能语义**，不承担装饰：
  1. **品牌绿 `#6E8269`** —— 严格说是**暖绿**（黄相）。它提供的是"暖色域内部的色相对比"，让暖木不至于糊成一片。**绝不可替换为冷绿**。
  2. **中性暖灰 `#CFC6B8`（纱罩）** —— 唯一的"去彩"元素，专门服务于"未解锁"的信息编码（§7/§9）。
- **禁止**：蓝、青、紫、洋红作为装饰色出现。**唯一例外**是"色盲友好模式"下把品牌绿/强调红重映射到蓝-橙对（§9.3）。

## 3. 光影与材质

### 3.1 光源规则（拼接一致性的第一红线）

| 项 | 规则 |
| --- | --- |
| **时间** | 傍晚 golden-hour，固定不变。**不允许出现夜景、正午、阴天** |
| **主光方向** | **从左上方 30–45° 射入**，地面影**向右下**延伸。实测 `1.jpg` / `2.jpg` / `主界面图` 三张的地面斜影方向一致，锁定此方向 |
| **主光色温** | ≈ 3200–3800K，暖橙 `sun-tint #E8A868` 叠加，强度克制 |
| **辅光（自发光）** | 室内暖光**无方向**（点光源感），色温 ≈ 2700–3000K，色 `glow-window #F2DDAE` |
| **环境光** | 极低强度冷灰米（`#C8C4BC`，不透明度 ≤ 12%），保证暗部**不死黑** |

**三条硬规则**：
1. **每一张立绘的光源方向必须锁定左上，影向右下。** 任何一张反向，拼进主界面立刻露馅——这是比"好看"更优先的一致性要求。
2. **橱窗内必须有自发光**，且亮度**高于外墙 1.5–2 档**。这形成"外墙米白 / 橱窗暖黄"的招牌式对比（实测主界面橱窗区均值 `#C8A889`–`#CCAC8C`，明显高于墙体 `#E3D8C8` 的暖度）。
3. **只做接触影（contact shadow），不做长投影**。软、短、不透明度 ≤ 25%。理由：主界面 5 个铺位横向并排，长投影会与相邻铺位打架。

### 3.2 四类材质的表现规则

#### 木（占比最高，最需要纪律）

- **三色阶**：暗 `wood-dark #6B4B3A` / 中 `wood-base #8F6049` / 亮 `wood-mid #A8764E`。
- **纹理**：细木纹以**横向**为主（与"正视图"的稳定感一致），纹路明暗对比 **≤ 10%**。禁止写实虫眼、结疤、裂纹（会显破败，违反"被照顾"）。
- **边缘**：用**浅色描边 `wood-light #C89A6E`** 勾 1–2px 亮边，营造"手作木作"的温度感。
- **禁止金属高光**。木的高光只能是柔和的宽面渐变。
- 例外：黄铜壁灯（`5.jpg`、`1.jpg`）是明确的小面积金属，允许金属高光——但全画面此类面积极小。

#### 布（雨棚 / 遮阳伞 / 窗帘 / 帷幔）

- **低饱和、哑光、无高光**。布面亮度一律低于其邻近的奶白墙。
- **条纹与波浪边**：条纹为等宽带，条带边缘**圆角收边**；波浪下摆为**规则半圆**，不做随机起伏。
- **褶皱**：只用 **2–3 条平行浅色带**表达，色差 ≤ 12%。**不做写实褶皱**（与扁平化风格冲突）。
- 雨棚配色分工（实测确认，需保持）：甜屋 / 咖啡 = **橙白条**；花束 = **粉白条**；衣橱 / 书店 / 一层空铺 = **纯色暖绿**。

#### 玻璃（橱窗 / 门 / 蛋糕柜）

- **不画"透明"本身，画"玻璃后面的东西"**：暖色内容物 + 暖光。
- **高光带**：一道 **45° 斜向白色高光带**，不透明度 **12–18%**，宽度约为玻璃面宽的 1/6。
- **极细描边**：玻璃边缘用 `wood-line #4A2F1E` 极细线勾勒（1px），让玻璃"有存在感"。
- **禁止玻璃反射像**（不画对面的建筑/天空倒影）。理由：主界面是正视图平面构成，反射像会引入第二套透视，直接破坏构图。

#### 绿植（画面唯一允许的高饱点缀）

- 叶色双阶：`leaf-deep #5C7A4A` / `leaf-light #7C9A5E`。
- 一簇 **2–3 片叶**，形状统一为**圆润水滴形**，不做锯齿边缘。
- 花用**点簇**：粉 `#F0A8B0` / 白 `#F7F0E2` / 橙 `#E8A868`（取 `blossom` 家族）。
- 花器统一三色：**陶土 / 米白 / 灰白**。
- **面积约束**：绿植总覆盖 ≤ 画面 8%（花束铺位单独可到其铺位面积的 35%，因为它是"花店"的身份特征）。

### 3.3 状态相关的光（预告 §7）

三种非开业状态**不改变上述光照规则**，只改变**该铺位局部的三件事**：自发光强度、是否加遮罩层、是否挂语义挂件。这样能保证"状态下的一层临街"和"开业中的一层临街"看起来仍在同一个傍晚、同一套光里。

### 4.4 构图规则（正视图平面构成的六条）

1. **实体分隔，不是空白分隔**。铺位之间**不做白色留白**，用**木质墙垛 / 竖框**分隔（11px @750，见上）。这是把五个铺位"缝"成一座完整商场的关键。
2. **地面是水平色带**。铺前街面是一条水平带（占 7.8%），**禁止透视收敛**、禁止铺地砖的梯形透视。
3. **楼层等宽**。二层不与一层做透视缩放，二者同宽（706px 可用宽）。
4. **顶部与底部的"框"**：绿色雨棚带（上）与木质 HUD 条（下）构成画面的上下框，让中间的双层商场像被"裱"进一个木质相框。
5. **视觉重心位于屏高 58%–62%**（≈ y 775–830 @1334），即**一层铺位与楼梯的交汇区**。该区应获得最高的明度对比与最多的高饱点缀（花束的花、咖啡的暖光）。
6. **铺位内安全框（8% 内缩）**：每个铺位内，立绘必须留出**至少 8% 的内边距**。原因很实际——现有素材是 AI 生图，**水印在右下角**、边缘常有杂物与不规则裁切，内缩 + 抠图时裁掉右下角才能保证拼接干净（详见 §10）。

### 5.5 体积预算

## 6. UI 视觉层级

> 本节是 **G8 主界面 IA/UX** 与 **G9 表现层**的视觉接口。信息**内容**归文策渊，视觉**优先级与状态表现**归本文件。

### 6.1 HUD 布局与信息优先级

HUD 独占屏幕底部 **160px @750（12.0%）**，其上留 **53px（4%）禁放区**。

| 优先级 | 元素 | 位置 | 视觉权重手段 | 理由 |
| --- | --- | --- | --- | --- |
| **P0** | **金币数值** | 左 | 最大字号 + 最高对比 + 金色图标 | 玩家最高频读取的信息（"我现在有多少钱"），对应 P2"一屏看懂" |
| **P1** | **3 个导航按钮**（经营/布局/好友） | 中 | 最大触控面积 + 立体木牌 + 图标 + 文字标签 | 行动入口，误触成本高，必须最大 |
| **P2** | **客流 已到店/上限** | 右 | 字号最小 + 分子重于分母 | 参考信息，不驱动决策；但仍须可读 |

**具体尺寸（@750）**

| 元素 | 规格 |
| --- | --- |
| 金币图标 | 48×48，与数值基线居中对齐 |
| 金币数值 | 字号 **40px**，字重 Heavy，色 `cream-bright #F2E8D8` |
| 导航按钮 | 直径 **96px**，图标 56×56 + 下方 22px 文字标签 |
| 按钮触控区 | **≥ 88×88**（不小于视觉直径，向下扩到 HUD 木条下缘） |
| 客流文本 | `已到店` 字号 **28px**（`cream-bright`）／`/上限` 字号 24px（不透明度 70%） |
| 客流图标 | 36×36（**新增**，现有素材缺） |

**权重公式（三条叠加，不靠颜色）**：`尺寸 > 对比 > 位置`。任何新元素进入 HUD，必须先回答"它排在 P0/P1/P2 的哪一位"，否则不许进（HUD 只放两个数字，见概念 P2）。

### 6.2 按钮三态

所有按钮（3 个导航按钮 + 解锁按钮 + 升级按钮）共用同一套状态语义。

| 状态 | 视觉处理 | 要点 |
| --- | --- | --- |
| **默认态** | 木牌受光；`wood-mid` 面 + `wood-light` 亮边 + `wood-line` 描边；图标为 `wood-pale` 浮雕 | 立体感来自**亮度分层**，不是来自金属高光 |
| **按下态** | 整体下沉 **2px** + 内阴影 + 亮度 **−12%** + 缩放 **×0.96**；**色相不变** | 禁止用颜色突变表达按下，暖调必须保持。下沉 + 变暗已足够形成"被按下去"的触觉反馈 |
| **禁用态** | 见下 §6.3（**不允许只用"变灰"**） | 这是可访问性硬要求 |

**动效时长**：按下 80ms，回弹 120ms，缓动 `ease-out`。**不设长于 200ms 的按钮动效**（HUD 是高频操作区，动效长了会"粘手"）。

### 6.3 禁用态的三重编码（可访问性硬要求）

概念文档 §9 与需求 R-02 都要求"金币不足时不能解锁**并给出原因**"。这决定了禁用态不能是"灰掉、点不动"：

| 编码 | 做法 | 作用 |
| --- | --- | --- |
| ① **形状** | 按钮右上角挂 `ico_lock` 角标 | 色盲可辨；余光可辨 |
| ② **文字** | 标签改为**具体原因**：「再攒 **N** 金币」（而非"金币不足"） | 不看颜色也能懂；且**告诉玩家差多少**，符合 P2 |
| ③ **明度** | 不透明度 **→ 78%**（不是更低的灰） | 保证对比度仍 **≥ 3:1**（可见性下限），避免"看不见的按钮" |

**禁止**：把禁用按钮变红（红色 = 错误/危险，违反"无失败态"）；把禁用按钮降到不可见（违反可见性下限）。

**可操作提示态**（金币刚好够解锁时）：在按钮上叠加**呼吸光晕**（1.6s 周期，明度 ±8%）+ 一个 `ico_plus` 角标。**呼吸幅度必须小**，避免在一个"放松"的游戏里制造视觉噪音。

### 6.4 木纹底上的文字可读性（与 §9 联动）

HUD 是木纹底，`cream-bright` 文字直接压上去时，落在木纹暗线的部位对比度会掉到 4.5:1 以下。**规则**：

- 所有压在木纹上的文字，**必须加其一**：① `rgba(58,38,24,0.35)` 的圆角衬底（半径 = 字号 × 0.25）；或 ② **2px `wood-line #4A2F1E` 描边**。
- 数值类文字**优先用方案 ②**（描边），因为它不改变布局盒尺寸，避免数字滚动时抖动。

## 7. 店铺状态表现方案【本任务核心专业判断】

### 7.1 问题定义

现有素材**只有"开业"一种立绘**（`3/4/5/8/9`）。主界面需要 **3 种状态**：

| 状态 | 语义 | 出现位置 |
| --- | --- | --- |
| **S1 未解锁 `locked`** | 这个铺位还不是你的，将来会有 | 二层 3 铺位（开局时） |
| **S2 已解锁未开业 `empty`** | 是你的了，但还没开店 | 开局的一层 2 铺位、二层解锁后 |
| **S3 已开业 `open`** | 营业中 | 已开店的铺位（**现有素材**） |

> ✅ **状态收敛说明（用户已拍板）**：**"手动关店"功能已从 v1 移除**（概念文档 §7 待确认项 1 的结论）。因此原先设计的 **S4「已关店」状态已从 v1 移除**——不再排期、不再出布帘（`ovl_shutter_closed`）资产、§7.5 的候选方案作废保留供后续版本参考。**本文档下文凡涉及 S4 的内容均已同步删除。**
> **对后续版本的提示**：若未来重新引入"每日营业开关"，S4 的编号与方案在 §7.5（已标记为"已移除/存档"）中保留，可直接复用，不必重做设计。

**共同约束**：
- 资产来源是 **AI 生图 + 抠图**，不是手工绘制。因此**任何"重绘"方案的成本都很高，且跨 5 个铺位的一致性不可控**。（注：SC-P1-005 已产出「资产基准模板 + 生成提示词」从生成端压一致性，见另一文档）
- 红线：**不允许出现失败态视觉**。所以 S1 **不能**用"破败、封条、红色、脏污"表达。
- 红线：**状态不可仅靠颜色区分**（§9.2）。

### 7.2 设计思路：正交编码

先把"区分维度"设计成正交的三条轴，再让每种状态占住不同的组合，这样**三态在任何一种色盲视角下都能区分**：

| 轴 | 取值 |
| --- | --- |
| **自发光** | 亮（橱窗暖光开）／ 暗（暖光收） |
| **遮挡** | 无／纱罩（半透明） |
| **符号** | 无／**锁**／**加号** |
| **文字** | 无／未开放／待开业 |

结果（**这就是推荐方案的骨架**）：

| 状态 | 自发光 | 遮挡 | 符号 | 文字 | 一句话读法 |
| --- | --- | --- | --- | --- | --- |
| **S1 未解锁** | 暗（30%） | **纱罩**（中性暖灰，35%） | **锁** | 「未开放」 | 还关着，以后会有 |
| **S2 已解锁未开业** | **亮（100%）** | 无 | **加号** | 「待开业」 | 灯亮着，等你来开店 |
| **S3 已开业** | **亮（100%）** | 无 | 无 | 店招 | 正在营业 |

> 关键：**S1 与 S2 的差别是"锁 vs 加号 + 纱罩 vs 无"**（形状+文字），**不是**颜色。全局只有 S1 引入了"去彩"，S2/S3 都在暖色域内。
> **S2 与 S3 的差别**靠"加号角标 + 「待开业」文字 vs 店招"承载——两者自发光都是 100%，所以**符号与文字通道是唯一的区分手段，不可省略**。

### 7.3 S1 未解锁 —— 三个候选方案

| 方案 | 做法 | 实现成本 | 视觉副作用 |
| --- | --- | --- | --- |
| **S1-A 仅去饱和降明** | 空铺底图去饱和 70–80% + 降明 25–35% | **极低**（一个材质参数，或预烘一张 PNG） | ⚠️ 全灰会读成"荒废/年久失修"，**滑向失败态**；且丢失铺位轮廓，看不出"这里将来是家店" |
| **S1-B 木板/围挡封挡** | 铺位前盖"施工围挡 / 钉死木板" | 中（新制围挡素材） | ❌ "钉死的木板"在东亚语境里 = 倒闭/停业，**明确违反无失败态**（方案否决） |
| **S1-C 纱罩 + 锁标记 + 文字** | 空铺底图 + 中性暖灰纱罩（35%）+ 木挂件「未开放」+ `ico_lock` 角标；自发光压到 30% | **中**（1 张纱罩 + 1 个挂件 + 1 个锁图标，全部可复用） | ✅ 保留铺位轮廓（能看出"这里将来是家店"），暖灰纱罩不冷、不脏；语义唯一 |

**推荐：S1-C**。理由：
1. **保留了"潜力"**。纱罩是"还没揭开"，不是"已经毁了"——这与 P3"慢慢变好"的预期方向一致（概念 §2.3 Progression）。
2. **中性暖灰 `#CFC6B8` 不是冷灰**。它仍在暖色域内，只是"去彩"，因此不会像灰度方案那样显得破败。
3. **锁形 + 文字承载全部语义**，颜色只是辅助（满足 §9.2）。
4. **成本可控**：纱罩可用九宫格缩放覆盖两个铺位尺寸，只需 1 张。

### 7.4 S2 已解锁未开业 —— 三个候选方案

| 方案 | 做法 | 实现成本 | 视觉副作用 |
| --- | --- | --- | --- |
| **S2-A 空铺 + 暖光点亮 + 木质「待开业」挂件** | 底图暖光拉满 + 挂件 + 加号角标 | **低**（复用 S1 挂件形状 + 1 个加号图标） | ✅ 最省；⚠️ 若暖光拉得太含蓄，会与 S1 分不开——必须靠"加号 + 无纱罩"来拉开差距 |
| **S2-B 加悬浮动效（加号上下浮动 + 光点粒子）** | 在 A 之上给加号做 1.5s 缓入缓出浮动 + 微光点 | 中（需动效，属 G9 范围） | ✅ 强引导，适合新手引导期；⚠️ 5 个铺位全动会变成视觉噪音，**只允许同时 1 个铺位播放** |
| **S2-C 幽灵预览（将要开的店的半透明立绘）** | 把 `shop_*_open` 以 30% 不透明度垫在空铺上 | 中高 | ⚠️ 强"抢先看"效果，但**容易被误读为"已经开了"**，与 S3 混淆，且需为每个铺位准备垫图 |

**推荐：S2-A 为主线 + S2-B 作为"仅新手期/仅被选中时"的可选增强**。
理由：
1. 与 S1 的差异由**三重编码**保证（无纱罩 + 加号 + 暖光满亮），不依赖颜色。
2. **"灯亮着"是本作最优雅的状态语言**——它把"可以开业"翻译成"这里有人、这里是活的"，符合"被照顾"的情绪词；而且它复用了 S3 已有的暖光语言，不需要新美术语言。
3. 加号的视觉母版直接复用现有 `18.jpg` 的加号语义，风格自动一致。
4. S2-C 否决：与 S3 混淆的风险大于它带来的惊喜感，且违反 P2"一屏看懂"。

### 7.6 推荐方案汇总与实现规格

| 状态 | 底图 | 自发光系数 | 叠加层 | 挂件文字 | 符号角标 | 动效 |
| --- | --- | --- | --- | --- | --- | --- |
| S1 `locked` | `slt_*_empty` | **0.30** | `ovl_veil_locked`（`#CFC6B8`，α 0.35） | 「未开放」 | `ico_lock` | 无 |
| S2 `empty` | `slt_*_empty` | **1.00** | 无 | 「待开业」 | `ico_plus` | 加号 1.5s 浮动（**同时仅 1 个**） |
| S3 `open` | `shop_*_open` | 1.00 | 无 | 店招（引擎文本） | 无 | 见 G9 |

**技术美术方案（已按程基岩 SC-P1-004 的引擎能力查证结论定稿）**：

- **不要出多套立绘**。S1/S2 共用一张空铺底图，S3 用开业立绘。差异全部由 **1 个材质自发光参数 + 1 张叠加层 + 2 个小图标** 承载。
- **✅ 引擎能力已确认**：Cocos Creator 3.8.8 **支持 2D 渲染对象自定义材质（最多 1 个）**，官方标准用法即运行时改参数：
  `spriteComp.customMaterial.setProperty('u_emissive', 0.30 / 1.00)`
- **因此走「一份材质 + 运行时参数」，不做多个预设 Material 变体**。理由：参数方案切换最轻、免维护多份材质、无额外内存常驻；预设变体方案反而要维护 N 份材质资产。
- 材质预设命名（仅作参数取值文档，不做成 3 个文件）：`mat_shop_locked`（`u_emissive=0.30`）/ `mat_shop_empty`（`1.00`）/ `mat_shop_open`（`1.00`）。
- **⚠️ 必须 M04 真机复验**：自定义 shader/材质在微信小游戏上**官方既未写"支持"也未写"不支持"，属"官方未设限、按引擎通用能力"**。已列入架构现状 §10 与 M04 验收项。**真机不复验通过，不得视为已落地。**
  - 有利事实：自定义材质在微信小游戏上官方未设限；Cocos 引擎自微信 7.0.7 起为内置插件，**不占主包 4MB**。
- **降级路径（若 M04 复验不通过）**：退化为"预烘 PNG 变体"。代价明确——**+300～500KB 体积、必须全预加载否则状态切换会闪烁、常驻内存升高**。**结论：首选参数方案，降级方案明确不如首选划算。**
- **状态收敛的资产收益**：若按"每个铺位每状态各出一张图"的朴素做法，3 状态 × 5 铺位 = **15 张**；实际只需 **2 张空铺底图 + 5 张立绘 + 4 张状态件（纱罩/挂件/锁/加号）= 11 张**，且其中 7 张（底图 + 立绘）本来就必须出。**即：三种状态表现本身只新增 4 张资产。** 移除 S4 又省下 1 张（布帘）。

### 7.7 顺带解决：店铺等级的"可见增长"

概念文档 §附录 A.2 冲突四指出"升级只有数值变化、违反 P3 看得见"。美术侧给出**低成本可见性阶梯**（不新增立绘，只改材质与挂件）：

| 等级 | 可见变化 | 成本 |
| --- | --- | --- |
| Lv1 | 基准 | — |
| Lv2 | 橱窗自发光 **+8%** | 参数 |
| Lv3 | 招牌上挂 **1 串小彩灯**（`prp_lights`） | 1 个资产，5 铺位复用 |
| Lv4 | 彩灯 **+ 门口 1 个花箱**（`prp_planter`） | 1 个资产 |
| Lv5 | 彩灯 + 花箱 + **招牌描金边**（材质描边色 → `gold`） | 参数 |

> 4 个等级变化只需 **2 个新资产 + 3 个参数**，就能让"慢慢变好"在场景里看得见。**这是美术侧对 P3 的正面回应。**
>
> ✅ **用户已采纳本完整四级阶梯**（SC-P1-005 派单确认），因此：
> - `prp_lights`（小彩灯串）与 `prp_planter`（门口花箱）**进入资产排期**，见另一文档《资产基准模板与生成提示词》§3 排期清单；
> - Lv2 的暖光 `+8%` 与 Lv5 的招牌描金**复用 §7.6 的同一套材质参数机制**（`u_emissive` / 描边色），不新增资产；
> - ⚠️ 与 §7.6 同一条依赖：**须经 M04 真机复验**自定义材质参数可用。

## 8. 字体方向

### 8.1 字体类型方向

与"暖木复古 + 正视图平面构成"匹配的中文字体需要三个特征：**笔画端部圆润**（对应木质圆角）、**中宫略松**（远看清晰，符合小屏 P2）、**有轻微手作感但不潦草**（对应"被照顾"而非"可爱过度"）。

| 用途 | 推荐 | 说明 |
| --- | --- | --- |
| **标题 / 招牌 / 店招 / 按钮标签** | **阿里巴巴普惠体 Heavy**（首选）或**站酷快乐体** | 普惠体字重齐全、授权最清晰；站酷快乐体更圆更暖，但字重少 |
| **数值 / 正文 / 说明** | **阿里巴巴普惠体 Regular** 或 **思源黑体（Source Han Sans / Noto Sans SC）Regular** | 思源是可靠的开源兜底（OFL） |
| **兜底策略** | 单一字体家族 × 2 字重（Regular + Heavy） | **全站只用 1 个家族**是最省体积、最容易保持一致的选择 |

**招牌立体字做法**：用字体 + 美术处理（`cream-bright` 填充 + `wood-line` 描边 2px + 底部 1px 深色投影 + 轻微透视压缩）实现，**不手绘字形**。这样改文案不必重出图。

### 8.2 授权风险清单【必读】

> ⚠️ 字体授权是**法律风险**，不是风格问题。以下为方向性判断，**任何一款在正式使用前都必须核对该字体官方的最新授权声明原文**。

| 字体 | 可商用? | 风险与说明 |
| --- | --- | --- |
| **思源黑体 / 思源宋体（Source Han）**、**Noto Sans SC** | ✅ **可** | SIL OFL 1.1，允许商用、允许嵌入、允许子集化。**最安全的选择** |
| **阿里巴巴普惠体** | ✅ **可** | 阿里官方声明免费商用。需保留授权声明并按官方条款使用 |
| **站酷系列**（站酷快乐体 / 高端黑 / 文艺体等） | ✅ 基本可 | 站酷官方声明免费商用；**逐款核对最新声明**（个别款有调整） |
| **得意黑 Smiley Sans** | ✅ **可** | OFL 授权。**注意**：字形风格强烈（斜切、现代），与本作"暖木复古"未必匹配，建议只用于局部强调 |
| **小米 MiSans** | ✅ 可 | 官方声明免费商用 |
| **方正系列**（方正静蕾、方正兰亭等） | ⚠️ **多数需付费** | 方正仅**部分**字款免费商用，且清单会变。**必须逐款核对官方免费商用清单**，不可默认可用 |
| **汉仪 / 华康 / 文鼎 / 蒙纳** | ❌ **需购买授权** | 商用授权费用高，**不可随包分发** |
| **微软雅黑 / 苹方 PingFang SC / 思源以外的系统字体** | ❌ **不可随包分发** | 系统字体**只能调用、不能打包**；且跨平台不一致（iOS 有苹方、安卓无），会导致不同机型不同观感。**本作不采用** |

**结论**：主字体取 **阿里巴巴普惠体**（或思源黑体兜底），**不使用任何需要付费授权或来源不明的字体**。上线前把"字体授权核对"列入发布检查清单。

### 8.3 现有素材的文字问题【必须整改】

**所有中文文字目前都是 AI 烘焙进像素的**（`街角商场 / 衣橱 / 甜屋 / 书店 / 咖啡 / 花束 / 经营 / 布局 / 好友 / 1280 / 36/50`），必须全部改为**引擎文本层**（TMP/Label）。理由，按优先级：

1. **无法修改**：金币数从 1280 变成 12800 时，"1280" 是图片像素，改不了。
2. **无法多语言**：将来任何本地化都要重出全部图。
3. **违反可访问性**：§9.4 要求文本可缩放到 ×1.3，位图文字缩放会糊。
4. **AI 中文不可靠**：生成式模型写汉字常有笔画错误、结构错误，正式素材不可接受。
5. **另有一处明确错误**：`14.jpg` 收银机上印有 **「TINAINA」**——这是 AI 生成的无意义拉丁字符串，**必须移除**，改为无字或改为中文「经营」字样（由文本层叠加）。

### 8.4 落地规格

| 项 | 规格 |
| --- | --- |
| 家族数 | **1 个** |
| 字重 | **2 个**（Regular / Heavy） |
| 字符集 | **子集化**：仅收录游戏实际用到的字符（中文约 200–400 字 + 数字 0-9 + 符号 `. / : ¥`），并**预留一档 buffer**（约 +30%）供后续文案微调 |
| 格式 | TTF（子集），必要时可转 WOFF2 进一步减小（**平台支持情况待核对官方文档**） |
| 体积目标 | **≤ 400KB**（未子集化的全量中文字体为 8–16MB 量级，**不可进包**） |
| 子集化时机 | **文案定稿后**再子集化；文案仍在变动期先用系统字体占位 |
| 字号（@750 基准） | 金币 40 / 客流 28 / 按钮标签 22 / 弹窗标题 34 / 弹窗正文 26 |
| 行高 | 字号的 1.4 倍 |
| 字距 | 标题 +2%，正文 0 |

## 9. 可访问性

> **定位**：可访问性是**基础要求**，不是加分项。**G8 主界面 IA/UX 规格必须引用本节的分级**；任何 UX 规格若与本节冲突，以本节为准（或由用户明确拍板豁免）。
> ✅ **平台事实已按程基岩 SC-P1-004 查证结论回修**：微信小游戏的「适老化 / 自动字号适配」**只面向小程序，小游戏不适用**。准确口径见 §9.4 —— 平台**提供**用户字号参数，但**适配必须由游戏自建**。本节的 Standard 档规格正是这个"自建"方案，**可落地**。

### 9.1 可访问性分级

| 分级 | 达标要求 | 本作目标 |
| --- | --- | --- |
| **Basic** | 对比度达标；关键信息不靠颜色单独承载；触控区 ≥ 44×44pt | ✅ **v1 必须达到** |
| **Standard** | Basic + 文本缩放 ≥ ×1.15 + 提供"减弱动效"开关 + 色盲友好模式 | ✅ **v1 争取达到** |
| Comprehensive | Standard + 文本缩放 ×1.3 + 音效/触感替代通道 + 完整键盘/外设支持 | ⬜ 不在 v1 范围 |
| Exemplary | 完整的屏幕阅读器支持与叙事可访问性 | ⬜ 不在 v1 范围 |

**v1 承诺：Basic 必须、Standard 争取。**

### 9.2 对比度下限

| 内容类型 | 下限 | 说明 |
| --- | --- | --- |
| 正文 / 说明文字 | **≥ 4.5:1** | WCAG AA |
| 大号文字（≥ 24px @750 或 ≥ 18px Bold） | **≥ 3:1** | WCAG AA 大字档 |
| **关键数值**（金币、客流） | **≥ 7:1**（争取） | 这是玩家"一屏看懂"的核心，按最高档要求 |
| 禁用态元素 | **≥ 3:1** | 禁用 ≠ 不可见（见 §6.3） |
| 图标（承载语义时） | **≥ 3:1** 与背景 | 图标不能"看不清但仍然必须看懂" |

**木纹底上的强制处理**：见 §6.4（文字必须加描边或圆角衬底）。实测木纹区均值在 `#8F6049`–`#A8764E` 之间，`cream-bright #F2E8D8` 直接叠加的对比度约为 4.2:1——**低于关键数值的 7:1 要求**，因此描边是**必需项而非优化项**。

### 9.3 色盲友好的信息编码【本节重点】

**铁律：颜色永远不是唯一的编码通道。**

#### 编码矩阵

| 信息 | 颜色（辅助） | **形状 / 图形（主）** | **文字（主）** | 明度差 |
| --- | --- | --- | --- | --- |
| **未解锁** | 去彩（暖灰） | **锁形角标** | 「未开放」 | 自发光 30%（暗） |
| **已解锁未开业** | 暖色 | **加号角标** | 「待开业」 | 自发光 100%（亮） |
| **已开业** | 暖色 + 高亮 | —（店招有形） | 店招文本 | 自发光 100% |
| **金币** | 金色 | **硬币圆形图标** | 数字 | — |
| **客流** | — | **人形图标** | `n/N` | — |
| **可解锁（金币够）** | 金色光晕 | **加号 + 呼吸** | 「解锁」 | 亮度脉动 |
| **不可解锁（金币不足）** | — | **锁形角标** | 「再攒 N 金币」 | 不透明度 78% |

**要点**：
1. **"解锁 / 未解锁"完全不用颜色承载**——锁形 vs 加号是形状差异，明度暗 vs 亮是明度差异，两套通道对**任何**色觉类型都成立。
2. **金币 vs 客流**不靠颜色区分（金色 vs 无色不可靠），靠**圆形硬币图标 vs 人形图标**的形状差异 + 文字标签。
3. **等级提升**（§7.7）不靠颜色，靠**挂件的有无**（彩灯 / 花箱）= 形状差异。

#### 色盲模式（Standard 分级要求）

| 项 | 做法 |
| --- | --- |
| 开关位置 | 设置项（若 v1 无设置页，则默认开启"高对比 + 形状强化"） |
| 红绿色盲（deutan / protan） | 避免红-绿对立。本作唯一的红绿组合风险是"品牌绿雨棚 vs 强调红邮戳"——二者**面积与位置差异极大**，不构成信息对立，风险低。色盲模式下把 `accent-red` 映射到 `#B26A00`（橙棕） |
| 蓝黄色盲（tritan） | 本作几乎无蓝黄组合，风险低 |
| 灰度检查 | **验收方法**：把主界面转灰度，确认 **3 种店铺状态仍然可区分**。若不可区分，退回 §7 修改编码 |

### 9.4 文本缩放、触控与动效

| 项 | 规格 |
| --- | --- |
| 文本缩放档位 | **×1.0 / ×1.15 / ×1.3**（×1.15 为 Standard 承诺档） |
| **⚠️ 字号来源的正确表述** | ❌ **不能**写成"跟随微信系统字号"——**小游戏是 canvas 渲染，官方那套适老化自动适配只面向小程序，小游戏不适用**。✅ 准确说法：平台**提供**用户字号参数（`wx.getAppBaseInfo`，旧接口 `wx.getSystemInfo` 的 `fontSizeSetting`），**适配必须由游戏自建**——即**读取该参数 → 映射到本作的三档缩放 → 驱动引擎文本字号**。**这是工程的活，但视觉规格由本节定义**（档位数值、HUD 高度上限、换行规则） |
| 缩放实现约束 | 缩放后 HUD 高度可增，但**总高度不超过屏幕 18%**；超出则字号回退并允许换行，**不允许裁切文字** |
| 触控区 | **≥ 88×88 @750**（约等于 44×44 pt）；相邻按钮间距 ≥ 16px |
| 动效 | 禁止 **> 3Hz** 的闪烁（光敏性癫痫风险）；金币数字滚动时长 **≤ 400ms**，`ease-out` |
| "减弱动效"开关 | Standard 档要求：开启后关闭加号浮动、光晕呼吸、粒子，保留必要的数值补间 |
| 音效替代 | 通知类反馈（如解锁成功）**音效 + 视觉双通道**，不单独依赖音效（属阮和鸣范围，此处仅记约束） |

### 9.5 给 G8 / G9 的接口要求

1. **G8（主界面 IA/UX）规格必须逐条引用 §9.1 的分级**，并明确"本规格达标到 Basic 还是 Standard"。
2. **G9（表现与反馈）在实现 §7 的三状态时，必须同时实现形状/文字通道**，不允许只做颜色/明度。特别注意 **S2（已解锁未开业）与 S3（已开业）自发光系数相同**，区分**只能**靠加号角标与文字——这两条通道不可省略。
3. 任何"用颜色区分"的提案，评审时一律要求回答："转灰度之后还分得开吗？"
